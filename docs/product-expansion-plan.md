# Product expansion implementation ledger

The requested expansion replaces the owner-only production adapter with GitHub OAuth accounts and explicit GitHub App installations. Existing verified jobs remain historical evidence.

## Delivery order

1. Register a public GitHub App using GitHub's manifest flow. Keep generated credentials in ignored local files and server secret stores.
2. Add encrypted OAuth credentials, hashed sessions, account data controls, installation/repository authorization, durable webhook ingestion and bounded automation to Neon.
3. Extend the agent to Python and Node/TypeScript pipeline coverage and maintenance, preserving existing workflow customization and isolated verification.
4. Build the public landing page, onboarding, dashboard, workbench, history, repository and account settings, documentation and product-specific legal pages.
5. Package the minimal-permission extension. It opens authenticated web actions and reads limited status through the web session; no GitHub credentials are stored in the extension.
6. Deploy, exercise seeded real workflows, permissions, duplicates, cancellation, disable/uninstall/deletion and browser entry points; record actual results and limitations.
