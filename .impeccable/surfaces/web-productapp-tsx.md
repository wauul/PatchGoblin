# Patch Bench replacement identity

Scope: the full React application, public reading surfaces and browser extension. Persuade on landing; Operate on authenticated routes; Read on help/legal pages. The user delegates choosing and implementing the direction without approval. Product facts come from PRODUCT.md and existing real jobs; inferred audience is labeled there. This session builds directly in code because the product needs real evidence and accessible controls, not illustrative mockups. No standing build-path preference is recorded.

Confirmed controls: appearance is one icon-only two-state sun/moon button. English/French selection uses a styled menu across desktop and phone, with checkmark, themed focus, full option names and a compact EN/FR phone trigger; the extension follows the same rule. The user's final language-menu instruction overrides the initial native language selector.

## Direction contract

THESIS: a repair bench for GitHub maintainers: the smallest supported patch sits between the original failure and its verification. Reject the old headline-plus-floating-card template and repeated promotional cards.

OWN-WORLD: Goblin forest #1B2D29, mascot lime #B6E572, cool light #F1F5F3; Public Sans for work, Barlow Semi Condensed for marketing display. Numbered sequence is reserved for actual agent phases; command receipts and selected tabs share the same inspection rule.

STORY: understand supported CI work, inspect a real public-lab repair, sign in, select access, launch a bounded job, review evidence and choose whether to merge.

FIRST VIEWPORT: slim navigation; a full-width compact headline with actions aligned alongside it; below, one horizontal three-part evidence bench (failure / minimal diff / verification), explicitly labeled as a real seeded example. No fake product screenshot. Lime actions and forest surfaces continue into the task interface.

FORM: Patch Bench, grounded candidate 3; seed key 3e25ce2f. Other candidates were Review Ledger, Maintenance Manual, shipping labels, patch queue, command receipts and a software workbook. Named signature interaction: keyboard-operable evidence tabs expose actual command counts and preserve the same evidence panel.

FINISH: unreviewed and undocumented is unfinished; this build ends with the finish review, the verdict, DESIGN.md, and every shipping raster carrying its provenance

## Challenger judgments

- Layered paper: declined on audience identification and product clarity. Raise: give surfaces and selected controls an explicit layer hierarchy.
- Sneaker archive: declined on audience identification and product clarity. Raise: put durable repository/job identification before ornamental chrome.
- Technical zine: competitive on explanation, weaker on operational density. Raise: let the mascot mark useful empty/loading states while factual evidence leads.
- Flight instruments: declined; the app lacks continuous quantitative telemetry. Raise: every status names its meaning and distinguishes sandbox verification from remote CI.
- Transparent printing: declined; overlapping source/evidence would impair reading. Raise: comparison is explicit and column-aligned.
- Toyism: declined; floating symbols obscure task affordances. Raise: one shared component/state vocabulary across all routes.

## Constraints

Keep working routes/APIs and actual measurements; no model calls for UI verification. Style desktop dropdown portals; use native mobile selects. Theme boot executes before paint with storage-denied fallback. Mobile uses five labeled workspace destinations with safe-area clearance. Preserve legal text meaning, explicit authorization and account-deletion confirmation.

## Confirmed brand alignment

The user explicitly asked for the palette and logo to match. The existing goblin.svg supplies the final accent #B6E572 and forest ink #1B2D29. Theme switching is one icon-only sun/moon button, with no visible text or theme menu. English and French are the current language choices.
